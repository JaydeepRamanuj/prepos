## Question
Implement structured data (JSON-LD) for an article page, a `sitemap.ts` that lists all questions and chapters, and a `robots.ts` that blocks private areas. Explain the XSS caveat with `dangerouslySetInnerHTML` for JSON-LD.

## Interview Answer
JSON-LD is a `<script type="application/ld+json">` tag in the page containing schema.org data such as `Article` or `BreadcrumbList`. In the App Router I render it from a Server Component with `dangerouslySetInnerHTML`, serialising the object with `JSON.stringify` and escaping `<` as `<` so user-controlled text can't close the script tag and inject HTML. A `sitemap.ts` route returns an array of entries (`url`, `lastModified`, `changeFrequency`, `priority`) generated from the same data source as the pages, and for very large sites `generateSitemaps` splits it into multiple files. `robots.ts` returns rules (`allow`, `disallow`, `sitemap`). All three are statically generated by default unless they use request-time data.

## Explanation
### JSON-LD component

```tsx
// components/json-ld.tsx
export function JsonLd({ data }: { data: Record<string, unknown> }) {
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{
        __html: JSON.stringify(data).replace(/</g, "\\u003c"),   // prevent </script> injection
      }}
    />
  );
}
```

```tsx
// app/tracks/[track]/[slug]/page.tsx
import type { Article, WithContext } from "schema-dts";   // optional types

export default async function Page({ params }: { params: Promise<{ track: string; slug: string }> }) {
  const { track, slug } = await params;
  const q = await getQuestion(track, slug);
  const jsonLd: WithContext<Article> = {
    "@context": "https://schema.org",
    "@type": "Article",
    headline: q.title,
    description: q.summary,
    datePublished: q.updatedAt,
    author: { "@type": "Organization", name: "PrepOS" },
    mainEntityOfPage: `https://prepos.dev/tracks/${track}/${slug}`,
  };
  return (
    <article>
      <JsonLd data={jsonLd} />
      {/* … */}
    </article>
  );
}
```

For FAQ-style content use `FAQPage`/`Question` types only where the page truly matches the guidelines; Google restricts rich results for FAQ/HowTo now, so use structured data to describe content accurately rather than chase rich results.

### Sitemap

```ts
// app/sitemap.ts
import type { MetadataRoute } from "next";

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const base = "https://prepos.dev";
  const questions = await getAllQuestions();        // same source as generateStaticParams

  return [
    { url: base, lastModified: new Date(), changeFrequency: "weekly", priority: 1 },
    ...questions.map((q) => ({
      url: `${base}/tracks/${q.track}/${q.slug}`,
      lastModified: q.updatedAt,
      changeFrequency: "monthly" as const,
      priority: 0.7,
    })),
  ];
}
```

Limits: 50,000 URLs or 50 MB per sitemap file; for larger sites export `generateSitemaps()` returning ids and receive an `id` Promise in the default function (async in Next.js 16).

### robots

```ts
// app/robots.ts
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [{ userAgent: "*", allow: "/", disallow: ["/api/", "/saved", "/account"] }],
    sitemap: "https://prepos.dev/sitemap.xml",
  };
}
```

`robots.txt` is advisory and public: don't use it to hide sensitive pages; use authentication and `noindex` metadata for pages that must not appear in results (and don't block them in `robots.txt` if you rely on a `noindex` tag, because crawlers must be able to fetch the page to see it).

### Checks
- Validate JSON-LD with Google's Rich Results Test or the Schema Markup Validator.
- Submit the sitemap in Search Console; check coverage.
- Keep `lastModified` truthful (a stable per-content value, not `new Date()` on every build).
- Canonical URLs in the sitemap should match canonical tags and exclude redirected URLs.

### Security
Anything interpolated into JSON-LD may come from content or users; JSON.stringify handles quotes, and the `<` escape handles the script-closing vector (also escape ` `/` ` for old parsers, though modern ones are fine).

## Follow-ups
- **Can I put JSON-LD in `generateMetadata`?** — Not directly; render the script in the page or layout.
- **Where does `sitemap.ts` run?** — At build time for static output, unless it uses request-time APIs.

## Common Mistakes
- Injecting unescaped strings into the script tag.
- Setting `lastModified: new Date()` for every entry.
- Blocking pages in robots.txt while expecting `noindex` to work.

## Tips
- Mention the `<` escape; it separates juniors from seniors here.
