## Question
Given these three routes, what is the resolved value of `params` for each URL? Which URLs 404?

```txt
app/blog/[slug]/page.tsx
app/shop/[...slug]/page.tsx
app/docs/[[...slug]]/page.tsx
```

```txt
1. /blog/hello
2. /blog/hello/world
3. /shop/clothes/tops/t-shirts
4. /shop
5. /docs
6. /docs/getting-started/install
```

Then write the page component for `app/shop/[...slug]/page.tsx` that prints the path as breadcrumbs. Use Next.js 16 APIs.

## Clues
- `[x]` matches exactly one segment, `[...x]` one or more, `[[...x]]` zero or more.
- Catch-all values are arrays.
- In Next.js 15+ `params` is a Promise.

## Interview Answer
`[slug]` matches exactly one segment, so `/blog/hello` gives `{ slug: 'hello' }` and `/blog/hello/world` 404s, because there's no route for two segments. `[...slug]` is catch-all and needs at least one segment, so `/shop/clothes/tops/t-shirts` gives `{ slug: ['clothes', 'tops', 't-shirts'] }` and `/shop` 404s unless there's a separate `app/shop/page.tsx`. `[[...slug]]` is optional catch-all, so `/docs` matches with `slug` undefined and `/docs/getting-started/install` gives `['getting-started', 'install']`. In Next.js 16, `params` is a Promise, so I `await` it in a Server Component or unwrap it with `use()` in a Client Component page.

## Explanation
### The answers

| # | URL | Route matched | `params` (resolved) |
|---|---|---|---|
| 1 | `/blog/hello` | `blog/[slug]` | `{ slug: 'hello' }` |
| 2 | `/blog/hello/world` | none | **404** |
| 3 | `/shop/clothes/tops/t-shirts` | `shop/[...slug]` | `{ slug: ['clothes', 'tops', 't-shirts'] }` |
| 4 | `/shop` | none | **404** (catch-all needs ≥ 1 segment) |
| 5 | `/docs` | `docs/[[...slug]]` | `{ slug: undefined }` |
| 6 | `/docs/getting-started/install` | `docs/[[...slug]]` | `{ slug: ['getting-started', 'install'] }` |

Types to match: `{ slug: string }`, `{ slug: string[] }`, `{ slug?: string[] }`.

### The breadcrumb page

```tsx
// app/shop/[...slug]/page.tsx
import Link from 'next/link'

export default async function ShopPage(props: PageProps<'/shop/[...slug]'>) {
  const { slug } = await props.params // string[]

  return (
    <nav aria-label="Breadcrumb">
      <Link href="/shop">Shop</Link>
      {slug.map((part, i) => {
        const href = '/shop/' + slug.slice(0, i + 1).join('/')
        return (
          <span key={href}>
            {' / '}
            <Link href={href}>{decodeURIComponent(part)}</Link>
          </span>
        )
      })}
    </nav>
  )
}
```

`PageProps<'/route'>` is a global type helper generated by `next dev`, `next build` or `next typegen` (since 15.5). Without it you'd write `{ params: Promise<{ slug: string[] }> }`.

### How it changed across versions

| Version | `params` |
|---|---|
| 13–14 | Plain object: `function Page({ params }) { params.slug }` |
| 15 | Promise, but synchronous access still worked with a warning (compatibility period) |
| 16 | Promise only; synchronous access removed |

Why a Promise? It lets Next.js start rendering before the params are needed, and lets you pass the promise down into a `<Suspense>` boundary, so a layout that doesn't await params can still be prerendered as part of a static shell.

### Client Component pages

```tsx
'use client'
import { use } from 'react'

export default function Page({ params }: { params: Promise<{ slug: string[] }> }) {
  const { slug } = use(params)
  return <p>{slug.join(' / ')}</p>
}
```

Elsewhere in a client tree, `useParams()` reads the current params without prop drilling.

### Precedence
Static segments win over dynamic ones. `app/shop/sale/page.tsx` serves `/shop/sale` even though `[...slug]` would also match.

## Follow-ups
- **How do you validate a param like `[locale]`?** — Check it against your known set at runtime and call `notFound()` if it's invalid. The URL is user input, so the type is `string` regardless of what you expect.
- **When would you choose optional catch-all?** — When one page should handle both the index and the nested paths, like a docs site where `/docs` and `/docs/a/b` share the same renderer.
- **Where else does `params` arrive?** — In `layout`, `route` handlers (second argument), `default`, `generateMetadata`, and metadata image files. All of them are async in 16.

## Common Mistakes
- Treating catch-all `slug` as a string and calling `.split('/')` on it.
- Forgetting that `[...slug]` doesn't match the bare parent path.
- Writing `params.slug` without `await` in Next.js 16. It's `undefined` on a Promise, and TypeScript flags it.

## Tips
- Memory hook: **one, one-or-more, zero-or-more**, the same as regex `x`, `x+`, `x*`.
- Always mention "params is async since 15, sync access removed in 16". Interviewers use it to check whether your knowledge is current.
